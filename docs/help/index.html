TTSTT Help

Quick start

Run slash commands in a server text channel. The channel where you run /join becomes the control channel for that server.

Text-to-speech (read chat in voice)

  1. Join a voice channel, then run /join in the text channel you want to use.
  2. Run /tts_listen_user and pick whose messages should be read aloud.
  3. Those users post in the same text channel; the bot speaks in voice.
  4. Optional: /tts_voice_set to customize your synthetic voice per server.
  5. Run /tts_stop_listening_user or /tts_stop_all_listeners when done.

Speech-to-text (voice to text)

  1. Run /join from your control text channel (same as above).
  2. Run /stt_listen_user for each speaker you want transcribed.
  3. When they speak in voice, transcripts appear in the control text channel.
  4. Run /stt_stop_listening_user or /stt_stop_all_listeners to stop.

In Discord, type /help anytime for a link back to this page.

Commands

Voice

Command What it does
/join Join your current voice channel and bind this text channel as the control channel.
/leave Disconnect from voice and clear listeners for this server.
/status Show voice connection, control channel, and how many TTS listeners are active.
/help Open this help guide (link sent in Discord).

Text-to-speech (TTS)

Command What it does
/tts_listen_user Start reading a user's messages from the control channel aloud in voice.
/tts_stop_listening_user Stop reading one user.
/tts_stop_all_listeners Stop reading all configured users in this server.

Speech-to-text (STT)

Command What it does
/stt_listen_user Transcribe a user's voice into the control text channel.
/stt_stop_listening_user Stop transcribing one user.
/stt_stop_all_listeners Stop transcribing all users in this server.

Voice preferences (per user, per server)

Command What it does
/tts_voice_set Set Deepgram voice/model, speed (0.5–2.0), pitch (−20–20), and optional style.
/tts_voice_show Show your saved TTS settings for this server.
/tts_voice_reset Reset your TTS settings to defaults for this server.

Privacy & safety

Before you use TTSTT: Voice and text in your server may be sent to speech AI providers for transcription and synthesis. Only add the bot where members understand and consent.
  • /join explains that STT and TTS may process user content in the server.
  • STT: Transcripts matching self-harm, medical, or minor-disclosure patterns are not posted publicly; the speaker may receive a private DM (including a 988 crisis line reference for self-harm matches). http:// and https:// URLs are replaced with [link removed] in public posts.
  • TTS: Listened messages with sensitive content or links are not synthesized or played in voice.
  • Set OPENAI_API_KEY on the bot host for additional hate, harassment, and violence screening via OpenAI's Moderation API (operator configuration, not end-user).

FAQ & troubleshooting

The bot does not respond to slash commands
Confirm the bot is online, invited with slash-command scope, and that command sync has finished after a deploy (global sync can take up to about an hour). Restart the bot after code updates.
/join fails or the bot never hears voice
The bot needs Connect, Speak, and View Channel in the voice channel. In the Discord Developer Portal, enable Guilds, Voice States, and Message Content privileged intents for the application.
TTS does not read my messages
Run /join in the text channel you want to use, then /tts_listen_user for your account. Messages must be posted in that same control channel while the bot is connected to voice.
STT does not post transcripts
Run /join, then /stt_listen_user for the speaker. They must be unmuted and speaking in the voice channel the bot joined. Sensitive speech may be DMed instead of posted publicly.
Voice sounds broken or the bot crashes in voice
The host running the bot needs FFmpeg and Opus support. Set FFMPEG_EXECUTABLE if ffmpeg is not on PATH.
Voice preferences do not save
The bot requires a working DATABASE_URL (PostgreSQL). Run schema init once: python -m apps.bot.init_db.
Who operates this bot?
TTSTT is a CSEN 174 team project (Noelle Evanich, Diego Silva, Dana Steinke). Server admins are responsible for inviting the bot and informing their community.
